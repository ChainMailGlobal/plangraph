PlanGraph — the drawing set as a graph

Every query below runs LIVE against HydraDB over its HTTP API. No cache, no LLM.

1 · Resolve a callout

A detail bubble on a plan says “5 / A902”. Does that detail exist on that sheet? One traversal: Callout → TARGETS_SHEET → Sheet → HAS_DETAIL → Detail.

—

2 · The dead end — absence is the defect

A callout referencing a sheet or detail the set does not contain. The graph doesn’t guess: the verdict was materialised at ingest, because a traversal that terminates in nothing IS the finding.

—

3 · Alias cluster — entity resolution

“A-452”, “A4.52”, “A452” are one sheet — the Track 01 Sam / @soham / S. Ratnaparkhi problem in construction clothing. Every raw spelling collapses to one node.

—

4 · Reverse trace

“Where is this sheet referenced from?” — reverse adjacency, one MATCH. In SQL this is a recursive CTE; here it is the natural direction of the same edges.
